Here is the full audit result, organized by severity:

Critical Bugs (broken functionality)
1. Script: RPC exportsCall() is broken
hijackMessage() at Script.java:374 is defined but never connected as the GLib signal handler. on("message", callback) wires the user callback directly to the GLib signal — there is no interception layer for "frida:rpc" responses. The CompletableFuture registered in RpcManager will never complete. Compare with Go script.go:141-146 where hijackFn replaces the message handler entirely.

2. Bus: all signals are dead
Bus.java:151-172 stores callbacks in a ConcurrentHashMap but never calls Closure.connectClosure(). Neither "detached" nor "message" are ever delivered to callers.

Missing Signal Support
3. Session has no on() method — the "detached" signal (Go: session.go:206) is not exposed.

4. DeviceManager has no on() method — Go exposes "added", "removed", "changed" signals (manager.go:196).

5. Script on() ignores "destroyed" signal — Script.java:242-267 silently drops any signal name other than "message".

Missing Session Methods
Go's Session exposes six methods Java is missing:

compileScript() — frida_session_compile_script_sync
snapshotScript() — frida_session_snapshot_script_sync
createScriptFromBytes() — frida_session_create_script_from_bytes_sync
setupPeerConnection() — frida_session_setup_peer_connection_sync
joinPortal() — frida_session_join_portal_sync
API Design Rule Violations (FFM Leakage)
Device.openChannel() and Device.openService() both return raw MemorySegment (Device.java:881, 907), violating the "No FFM leakage" rule from CLAUDE.md. Both need proper wrapper classes.
